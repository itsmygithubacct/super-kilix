# Data, graphics, and audio provenance

This document catalogs where every byte of Super Kilix's content comes from.
Every player-visible byte is generated by code at runtime; the game ships and
loads no asset files. The originality claim it supports is stated in full in
[originality.md](originality.md).

## Graphics

Super Kilix ships **no image assets**. Every character, tile, background, effect,
and HUD element is drawn at runtime from the soft-raster primitive set
(rectangles, outlines, circles, ellipses, rings, lines, triangles, diamonds, and
a built-in bitmap font). The renderer is a three-canvas pipeline — a fixed
256×240 logical canvas is nearest-scaled to the terminal's pixel size, packed to
RGBA, and presented through the Kitty graphics protocol.

Kilix himself is composed entirely from these primitives — an orange body with a
dark-orange fur pair, pink inner ears, a dark-teal visor with a cyan glint, cyan
magnetic boots, a violet micro-thruster, and an animated tail — so he is drawn
identically to his appearance in the sibling salvage game, sharing the
established character and its gait model but no image data. The guardian
machines, the eight per-district world motifs, and every menu, HUD, and manual
screen are drawn the same way. The full catalog is in
[originality.md](originality.md).

Every drawing call is routed through file-static wrappers so simulation state is
never read or written by the renderer; `--render-test` proves this by comparing
`GameState` with `memcmp` around every scene.

## Data

Level content is generated deterministically. `level_build(index, &out)` is a
pure function of the vault index: no external files, no random assets, no globals
beyond the index. It rebuilds byte-for-byte identically across runs, which
`--rules-test` verifies. The vault format is an original compact encoding — a
two-byte-per-object stream layered over a default terrain pattern, with a
parallel camera-relative spawn stream — structurally inspired by the genre's
diff-against-a-floor idea but carrying zero copied bytes or layouts.

The campaign is eight districts of four vaults each (32 total). Each vault has a
unique FNV-1a topology signature and a validated, reachable entry-to-exit route;
`level_validate_campaign()` enforces distinctness, reachability, floor
continuity, and per-vault budgets. Inspect any of it headlessly with
`--dump-campaign` and `--dump-level N`.

Player progress is the only thing the game writes to disk: a small, versioned,
checksummed, fixed-size binary profile at
`${XDG_DATA_HOME:-$HOME/.local/share}/super-kilix/profile.v1`, written mode-0600
via a temporary file, `fsync`, atomic rename, and directory `fsync`. It holds a
magic number, schema version, high score, deepest unlocked district, a sound
flag, reserved bytes, and a checksum; a corrupt or newer file is ignored without
partial application.

## Audio

Super Kilix ships **no audio assets** — no samples, no recordings, no imported
tracker modules. Every note is an **original composition**, and every sound is
synthesised in memory at runtime from original data tables. Nothing is
transcribed, quoted, or lightly altered from any other work; only the synthesis
*technique* (duty-pulse leads, an octave-down triangle bass, gapped-noise
percussion, table-stepped pitch sweeps) is reused, which is non-copyrightable.

### Synthesis path

`src/sound.c` is the only module that includes the audio headers. It pairs two
vendored libraries:

- **chip-sequencer** — the deterministic *source*: it bakes compact in-source
  song data (patterns of note cells + table-driven instruments) into PCM with a
  libm-free fixed-point chip synth (pulse / triangle / noise / wavetable). Its
  render path contains no transcendentals, so a given `(song, options, rate)` is
  byte-identical forever. Vendored as `third_party/chip-sequencer` and compiled
  into the binary by `src/vendor_chip_sequencer.o` with the game's own flags
  (which carry `-ffp-contract=off`), never as a shared or static archive.
- **pcm-mixer** (from `kilix-game-kit`) — the *transport*: device, mixer thread,
  and voice model. The whole seam is one function pointer,
  `pcmmix_set_generator(&mixer, chipseq_generator, &seq)`.

Audio is optional and never fatal: if no sink is found, the game runs silently
and `--sound-test` still returns `0`.

Twelve original songs — a title theme, one bed per district, a boss theme, and
two stings:

| "Vault Reveille" | title theme |
| "Sunward Run" | RUST FLATS bed |
| "Underhum" | COIL WARRENS bed |
| "Driftsong" | NULL TIDE bed |
| "Skyrail Sprint" | RAIL SPIRES bed |
| "Forgelight" | THE CINDERWORKS bed |
| "Undertow" | DROWNED CELLS bed |
| "Slagworks" | EMBER CONDUITS bed |

District beds run **live** through the sequencer so the global effect duck lowers
the music while an effect sounds.

### Effect catalog

Thirteen effect roles, each a one- or two-channel song synthesised by technique
and indexed by the `SFX_*` enum: jump, land, stomp, shell-kick, phase-bolt,
power-up, hurt, pickup, extra-life, exit-open, boss-hit, low-charge, and the held
thruster drone (loop-controlled live). They are wired to the gameplay events
(jump and land in the physics; stomp, kick, hurt, power-up, pickup, boss-hit, and
exit in the interaction code).

### Determinism

`--sound-test` first runs an offline gate (`sound_render_selfcheck`) that
validates every song and effect and renders a fixed span of a district bed
**twice** through the offline bounce path, asserting the two are byte-identical.
This runs with or without an audio sink and is exercised by both `make test` and
`make sanitize`.

## Clean-room enforcement patterns

`make clean-room-check` is a prerequisite of `make test`. It prunes `./.git` and
`./third_party` and then applies three checks:

1. **No reference-format asset files.** A `find` fails the build if any file in
   the tree matches these extensions (case-insensitive):

   ```
   *.nes  *.nsf  *.chr  *.prg  *.fm2  *.bk2  *.pal
   ```

   These are the artifacts a careless port would leak — a ROM, a music dump, a
   character sheet, a program bank, a movie capture, or a palette.

2. **No forbidden brand or expression tokens.** A case-insensitive `grep -R -E`
   over `src`, `docs`, and `README.md` fails the build if any prior game's title,
   character name, or publisher brand appears. Because this search covers the
   docs and the README, not just the source, every shipped document — including
   this one — states its claims *generically* and contains none of the tokens it
   forbids. The exact literal set lives only in the `Makefile`.

3. **No publishing-hygiene tokens.** A second case-insensitive `grep` over the
   same paths fails the build if a tooling-vendor string appears anywhere in the
   shipped tree.

The research and reference material that names the studied genre and its
exemplars freely is kept permanently outside the repository and is never added to
it, so the grep never sees it.
